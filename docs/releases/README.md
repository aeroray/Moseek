# 发布说明

每次正式发版前，在这个目录里写一份 `<标签>.md`，例如 `v1.0.0.md`。

发布工作流（`.github/workflows/release.yml`）会用 `scripts/load-release-notes.mjs`
读取它作为 GitHub Release 的正文；**文件不存在时工作流会直接失败**——这是刻意的，
免得某次发版忘了写说明、结果把上一版的说明当成本版的发出去。

约定：

- **文件名必须与标签完全一致**，含 `v` 前缀：`v1.2.3.md`。
- 内容用 Markdown，会原样作为 Release 正文；不要在正文里出现 `RELEASE_NOTES_EOF`。
- 面向用户写：说清这一版能用来做什么、修了哪些他会碰到的问题，不必罗列内部改动。
- 目前这个目录是空的：项目尚未正式发版，第一份说明等到发版时再写。

本文件本身不会被打进发布正文，它只是占住目录并留下约定。
